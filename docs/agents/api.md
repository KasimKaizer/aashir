# Package API

Rules for the supported import surface. Read this before adding or renaming a public name, or before changing a provider-visible schema.

- `aashir.agent` and `aashir.tools` are the supported package import surfaces. Re-export supported names in each package's `__init__.py` and list them explicitly in `__all__`.
- `aashir.tools` exports `ToolDefinition`, `RunnableTool`, `ToolCatalog`, `ToolCatalogError`, `ToolCatalogRejection`, `UncertainToolEffect`, `read_file`, `write_file`, `edit_file`, `ReadFileArguments`, `WriteFileArguments`, `EditFileArguments`, `TextEdit`, `generic_validation_error_message`, and `DEFAULT_TOOL_ARGUMENT_BYTE_CAP`. `read_file`, `write_file`, and `edit_file` are ordinary `ToolDefinition` values. The caller that starts a run, such as the CLI, builds a `ToolCatalog` from the tools it selects. `AgentRequest.tools` carries that catalog. `run_agent` advertises `provider_tools()` from it and dispatches with `ToolCatalog.execute`. An empty catalog advertises and runs no tools. A caller passes `generic_validation_error_message` as `validation_error_formatter` when the tool should use the shared validation text.
- A name that appears in an exported signature, or in the type of an exported value, is exported from the same package. `ToolCatalog.definitions` is a tuple of `RunnableTool`, so that protocol is exported. `read_file`, `write_file`, and `edit_file` are typed with `ReadFileArguments`, `WriteFileArguments`, and `EditFileArguments`. `EditFileArguments` refers to `TextEdit`, so that model is exported too.
- Examples and tests that exercise supported public behavior import from these package facades, not from implementation modules. A direct import from an implementation module is not a supported public API.
- Prefix module-level implementation-only helpers, classes, and constants with `_`. Internal modules and focused unit tests may import these names directly. That import does not make them public.
- Keep CLI entry points and framework hooks under the names their callers require. They are entry points, not general package API.
- Pydantic models used in provider-visible JSON Schema keep public, unprefixed class names. Add a one-line comment saying why: Pydantic derives `$defs` and `$ref` keys from the class name, and the provider sees those keys. Export a model when an exported signature or an exported value uses it. Leave every other schema model out of `__all__`. Test the generated schema when renaming one.
